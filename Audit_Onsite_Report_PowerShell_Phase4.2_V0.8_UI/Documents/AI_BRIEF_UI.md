## 0. คำสั่งสรุป (ถ้าจะอ่านแค่ย่อหน้าเดียว)

> ปรับปรุงเฉพาะชั้น UI ของโปรแกรม Audit Onsite Report ที่แนบมา โดยใช้ Windows PowerShell 5.1

## 1. บริบทของโปรแกรม

โปรแกรมช่วยผู้ตรวจสอบภายในสาขาธนาคาร สร้างไฟล์ Word "สรุปรายงานผลการตรวจสอบ"
ทำงานออฟไลน์บนเครื่อง Windows ของผู้ใช้

ขั้นตอนการใช้งาน 4 ขั้น
1. กรอกข้อมูลหัวรายงาน 15 ช่อง
2. เลือกไฟล์ Excel ผลตรวจ แล้วให้โปรแกรมอ่านค่าอัตโนมัติ (ตอนนี้อ่านได้จริงแค่ข้อ 3.2)
3. กรอกหรือแก้ผลตรวจ 11 ข้อ
4. ตรวจ Word Template แล้วสั่ง Export

**ผู้ใช้จริง**: เจ้าหน้าที่ตรวจสอบภายใน อายุเฉลี่ยค่อนข้างสูง หลายคนสายตายาว
ใช้โน้ตบุ๊กจอ 14 นิ้ว ความละเอียด 1920x1080 และมักตั้ง Windows Display Scaling ไว้ที่ 125%

## 2. ข้อจำกัดทางเทคนิคที่เปลี่ยนไม่ได้

- ต้องรันบน **Windows PowerShell 5.1** เท่านั้น (ไม่ใช่ PowerShell 7)
- เปิดผ่าน `Run-AuditOnsiteReport.bat` ซึ่งเรียก `-STA -NoProfile -ExecutionPolicy Bypass`
- ใช้ได้เฉพาะ **Windows Forms** ที่มากับ .NET Framework
- **ห้ามใช้ NuGet, ห้ามโหลด DLL ภายนอก, ห้ามต่ออินเทอร์เน็ต** เพราะต้องทำงานออฟไลน์
- ไฟล์ `.ps1` และ `.psm1` ทุกไฟล์ต้องบันทึกเป็น **UTF-8 with BOM**
  ไม่งั้น PowerShell 5.1 จะอ่านภาษาไทยเพี้ยนทั้งไฟล์

## 3. สิ่งที่ห้ามแตะ (Business Rules)

- ห้ามแก้ `Modules/AuditOnsite.Word.psm1` (Word Export Engine ที่ทดสอบแล้ว)
- ห้ามแก้ `Modules/AuditOnsite.Excel.psm1` (Excel COM เปิดแบบ Read-only)
- ห้ามแก้ `Modules/AuditOnsite.Core.psm1` `Config/` `Templates/`
- ห้ามลดข้อมูลหัวรายงานจาก **15 ช่อง**
- ห้ามลบปุ่ม **จำค่า (Fix)**, **ล้างค่าจำทั้งหมด**, **เริ่มสาขาใหม่**
- ต้องคง Gate เดิมทุกข้อ
  - Export ถูก Block ถ้าข้อมูลจำเป็นไม่ครบ หรือผลตรวจข้อใดข้อหนึ่งยังว่าง
  - ต้องกดตรวจ Template ผ่านก่อน ปุ่ม Export จึงทำงาน
  - ต้องมีหน้าต่างยืนยันก่อนสร้างไฟล์ กดยกเลิกแล้วต้องไม่มีไฟล์เกิดขึ้น
  - Output ต้องเป็นไฟล์ใหม่เสมอ ห้ามทับไฟล์เดิม
- ห้ามแก้หรือบันทึกทับไฟล์ Excel ต้นฉบับ

### 4.2 ฟอนต์

- เลือกฟอนต์อัตโนมัติจากที่เครื่องมีจริง ตามลำดับ
  `Leelawadee UI` -> `Leelawadee` -> `Segoe UI` -> `Tahoma` -> `Microsoft Sans Serif`
- ตรวจด้วย `[Drawing.FontFamily]::Families` ห้ามฮาร์ดโค้ดชื่อฟอนต์ตัวเดียว
- ขนาดฟอนต์ให้ดูหัวข้อ 5 (เปลี่ยนใหม่รอบนี้)

### 4.3 คอนโทรลมาตรฐาน

- **ปุ่ม**: `FlatStyle = Flat`, `BorderSize = 1`, กำหนด `MouseOverBackColor` เอง, `Cursor = Hand`
  - Primary = พื้น Accent ตัวหนังสือขาว / Secondary = พื้นขาว ขอบ Border
- **การ์ด**: พื้นขาว วาดขอบ 1 พิกเซลและแถบสี Accent กว้าง 4 พิกเซลด้านซ้ายผ่าน `Add_Paint`
- **ป้ายสถานะ (Badge)**: `Label` ที่มี `Padding` และพื้นสีอ่อน ตัวหนา
- **ตาราง**: `DataGridView` ปิด `EnableHeadersVisualStyles` แล้วกำหนดสีหัวตารางเอง
  แถวสลับสี 249,251,253 เปิด `ShowCellToolTips`

## 5. ข้อกำหนดใหม่รอบนี้: ตัวอักษรใหญ่และปุ่มขยาย

**เหตุผล: ผู้ใช้จำนวนมากเป็นผู้สูงอายุ ต้องอ่านได้ชัดโดยไม่ต้องเพ่ง**

### 5.1 ขนาดฐานใหม่ (ที่ระดับซูม 100%)

| ใช้กับ | เดิม V0.8 | **ค่าใหม่ที่ต้องใช้** |
|---|---|---|
| ข้อความในช่องกรอกและช่องผลตรวจ | 10.5 pt | **13 pt** |
| ป้ายชื่อช่อง ปุ่ม เมนู | 10 pt | **12 pt** |

### 5.2 ปุ่มขยาย

- วางปุ่มขยายไว้ที่ **แถบหัวโปรแกรมด้านขวา** ให้เห็นตลอดทุกหน้า
- มี 3 ปุ่ม: `ก-` `ก` `ก+` ขนาดปุ่มไม่ต่ำกว่า 44x40 พิกเซล พร้อม ToolTip ภาษาไทย
- ระดับซูม 4 ระดับ: **100% / 125% / 150% / 175%** ปุ่ม `ก` คือคืนค่ากลับ 100%
- แสดงระดับปัจจุบันเป็นตัวเลขข้างปุ่ม เช่น `125%`
- คีย์ลัด `Ctrl` + `+` ขยาย, `Ctrl` + `-` ย่อ, `Ctrl` + `0` คืนค่า
- **จำระดับซูมไว้** ในไฟล์ `Config/UI_Settings.json` (สร้างใหม่ได้ ห้ามไปยัดใน `Fixed_Values.json`
  เพราะไฟล์นั้นเก็บค่าข้อมูลรายงานที่ผู้ใช้ติ๊กจำไว้) เปิดโปรแกรมครั้งหน้าต้องได้ขนาดเดิม

### 5.3 กฎสำคัญ: ต้องขยายทั้ง Layout ไม่ใช่ขยายแค่ฟอนต์

ถ้าขยายแต่ฟอนต์แล้วปล่อยความสูงคงที่ไว้ ตัวหนังสือจะถูกตัดครึ่ง นี่คือข้อผิดพลาดที่พบบ่อยที่สุด
ทุกค่าขนาดต่อไปนี้ต้องคูณด้วยตัวคูณซูมด้วย

- ความสูงช่องกรอก (เดิม 28), ความสูงปุ่ม (เดิม 38), ความสูงป้ายชื่อช่อง (เดิม 30)
- ความสูงช่องผลตรวจ (เดิม 86), ความสูงแถวตาราง (เดิม 30), ความสูงหัวตาราง (เดิม 34)
- ความกว้างเมนูซ้าย (เดิม 262), ความสูงปุ่มเมนู (เดิม 62), ความสูงแถบหัว (เดิม 84)
- ความกว้างคอลัมน์ป้ายชื่อช่อง (เดิม 258) และคอลัมน์ปุ่มจำค่า (เดิม 96)
- ความกว้างปุ่มทุกปุ่ม เพราะข้อความไทยจะยาวขึ้นตามฟอนต์

### 5.4 วิธีทำที่แนะนำ

ให้เก็บตัวคูณไว้ที่เดียวใน Theme แล้วให้ทุกขนาดผ่านฟังก์ชันเดียวกัน

```powershell
# ใน AuditOnsite.Theme.psm1
$script:UiScale = 1.0
function Set-AuditUiScale { param([double]$Scale) $script:UiScale = $Scale }
function Get-AuditUiScale { return $script:UiScale }
# ใช้กับขนาดพิกเซลทุกจุด เช่น Get-AuditScaled 28
function Get-AuditScaled { param([int]$Value) return [int][Math]::Round($Value * $script:UiScale) }
# ใช้กับฟอนต์ทุกจุด
function New-AuditFont {
    param([double]$Size = 12,[string]$Style = 'Regular')
    $fontStyle = $(if ($Style -eq 'Bold') { [Drawing.FontStyle]::Bold } else { [Drawing.FontStyle]::Regular })
    return (New-Object Drawing.Font($script:FontFamily,[single]($Size * $script:UiScale),$fontStyle))
}
```

เวลาผู้ใช้กดปุ่มขยาย ให้ **สร้างหน้าต่างใหม่ทั้งหน้าต่าง** ซึ่งง่ายและพลาดยากกว่าการไล่แก้ทีละคอนโทรล
ขั้นตอนคือ

1. เก็บค่าปัจจุบันลง Hashtable ธรรมดา (ข้อความทุกช่อง, ผลตรวจ 11 ข้อ, แหล่งข้อมูลรายข้อ,
   รายการไฟล์ Excel, สถานะ Template, หน้าที่กำลังเปิดอยู่)
2. บันทึกระดับซูมลง `Config/UI_Settings.json`
3. เรียก `Set-AuditUiScale` ด้วยค่าใหม่
4. ปิดหน้าต่างเดิมด้วย `$form.Close()`
5. เปิด `Start-AuditOnsiteUI` ใหม่แล้วเติมค่าที่เก็บไว้กลับเข้าไปทุกช่อง

**ห้ามให้ผู้ใช้ต้องกรอกข้อมูลใหม่หลังกดขยาย** ข้อนี้ถือว่าไม่ผ่านการตรวจรับ

### 5.5 ข้อกำหนดอื่นสำหรับผู้สูงอายุ

- เปลี่ยนสีข้อความรอง TextMuted จาก 108,117,127 เป็น **90,99,110** เพื่อเพิ่ม Contrast
- ห้ามใช้ข้อความสีเทาอ่อนบนพื้นขาวเป็นข้อมูลสำคัญ
- พื้นที่กดของปุ่มทุกปุ่มต้องไม่ต่ำกว่า 40 พิกเซลที่ซูม 100%
- ระยะห่างระหว่างปุ่มไม่ต่ำกว่า 10 พิกเซล กันการกดพลาด
- ข้อความบอกข้อผิดพลาดต้องบอกว่า **ต้องทำอะไรต่อ** ไม่ใช่บอกแค่ว่าผิด
  เช่น "ยัง Export ไม่ได้ กรุณากรอกช่อง 2.3 เลขที่อนุมัติแผนตรวจสอบ"
- อย่าสื่อสถานะด้วยสีอย่างเดียว ต้องมีข้อความกำกับเสมอ เพราะมีผู้ใช้ตาบอดสี
- ตรวจให้แน่ใจว่าใช้งานได้จริงเมื่อ Windows Display Scaling อยู่ที่ 125% และ 150%

## 6. กับดักของ PowerShell 5.1 ที่ต้องระวัง (เคยพลาดมาแล้วจริง)

1. `New-Object Drawing.Point(x,y)` ในบางบริบทตีความอาร์กิวเมนต์ผิด
   ให้ใช้ `New-Object Drawing.Point -ArgumentList $x, $y` หรือกำหนดผ่าน `.Location`
2. Pipeline ที่คืนค่ารายการเดียวจะไม่มี `.Count` ให้ครอบด้วย `@( )` เสมอ
3. **ห้ามตั้งชื่อตัวแปรว่า `$host`** เพราะทับตัวแปรอัตโนมัติของ PowerShell
   (V0.7 เคยใช้แล้วมีปัญหา) ชื่อที่ควรเลี่ยงอีก: `$input` `$error` `$args` `$this`
4. Event Handler ที่สร้างในลูป ต้องปิดท้ายด้วย `.GetNewClosure()`
   และ **ตัวแปรที่สร้างทีหลังจะไม่อยู่ใน Closure** ให้ประกาศ Scriptblock ที่ต้องเรียกใช้ก่อนเสมอ
5. `Set-StrictMode -Version Latest` เปิดอยู่ การอ่าน Property ที่ไม่มีจริงจะพัง
6. เวลาส่ง Argument ให้ Explorer ต้องเขียนแบบนี้
   `Start-Process explorer.exe -ArgumentList ('/select,"' + $path + '"')`
   ห้ามต่อสตริงด้วยเครื่องหมายบวกนอก ArgumentList (V0.7 เคยเขียนผิดจนเปิดโฟลเดอร์ไม่ตรงไฟล์)
7. ในหน้าต่างที่มีทั้งแถบบนและพื้นที่เต็ม ให้เพิ่มคอนโทรลที่ `Dock = 'Fill'` **ก่อน**
   คอนโทรลที่ `Dock = 'Top'` ไม่งั้นแถบหัวจะถูกทับ
8. ห้ามวางคอนโทรลด้วยพิกัดตายตัว ให้ใช้ `TableLayoutPanel` และ `Anchor` ทั้งหมด
   ยกเว้นคอนโทรลไม่กี่ตัวในแถบหัวและแถบสถานะ
9. อย่าสร้างตารางใหม่ทุกครั้งที่ Timer ทำงาน ให้เทียบลายเซ็นข้อมูลก่อน ไม่งั้นตารางจะกะพริบ
10. ทดสอบด้วย `[System.Management.Automation.Language.Parser]::ParseFile()` ก่อนส่งงานเสมอ

## 7. เกณฑ์ตรวจรับ (ต้องผ่านทุกข้อ)

**กลุ่ม ก - ของเดิมต้องไม่พัง**
1. เปิดโปรแกรมผ่าน `Run-AuditOnsiteReport.bat` ไม่มี Error
2. ข้อมูลหัวรายงานยังครบ 15 ช่อง
3. ปุ่มจำค่า ล้างค่าจำ เริ่มสาขาใหม่ ยังอยู่และทำงานถูกต้อง
4. Scan ข้อ 3.2 แล้วขึ้นแหล่งข้อมูล AUTO_DRAFT
5. ตรวจ Template แล้วขึ้น Placeholder 28/28 และปุ่ม Export เปิดใช้งาน
6. กด Export แล้วกดยกเลิก ต้องไม่มีไฟล์เกิดขึ้นใน `Output/`
7. กดยืนยัน ได้ไฟล์ใหม่ Placeholder ตกค้าง 0 และรูปแบบเอกสารไม่เปลี่ยน

**กลุ่ม ข - เรื่องการมองเห็น**
8. ทุกข้อความในโปรแกรมมีขนาดไม่ต่ำกว่า 11 pt
9. ปุ่มขยายอยู่บนแถบหัว เห็นได้ทุกหน้า และมี ToolTip
10. กดขยายไป 125% 150% 175% แล้ว **ไม่มีตัวหนังสือถูกตัด ไม่มีปุ่มซ้อนกัน ไม่มีอะไรหลุดขอบ**
11. กดขยายแล้วข้อมูลที่กรอกไว้ยังอยู่ครบทุกช่อง
12. ปิดโปรแกรมแล้วเปิดใหม่ ต้องได้ระดับซูมเดิม
13. คีย์ลัด `Ctrl` `+` `-` `0` ทำงานถูกต้อง
14. ย่อหน้าต่างจนเล็กสุดที่ 175% แล้วยังใช้งานได้ ไม่มีอะไรหลุดขอบ
15. ทดสอบบน Windows Display Scaling 125% ผ่าน

**กลุ่ม ค - คุณภาพโค้ด**
16. ไฟล์ `.ps1` และ `.psm1` ทุกไฟล์เป็น UTF-8 with BOM
17. `Word.psm1` `Excel.psm1` `Core.psm1` `Config/` `Templates/` เหมือนเดิมทุกไบต์
    (ตรวจด้วยการเทียบ Hash)
18. ทุกไฟล์ผ่าน Parser โดยไม่มี Error
19. ค่าขนาดและสีทุกค่ามาจาก `AuditOnsite.Theme.psm1` ที่เดียว ห้ามฮาร์ดโค้ดกระจาย

## 8. สิ่งที่ต้องส่งมอบ

1. ZIP ทั้งโฟลเดอร์ที่รันได้ทันที
2. รายการไฟล์ที่แก้ พร้อมเหตุผลสั้น ๆ ต่อไฟล์
3. ผลการตรวจรับหัวข้อ 7 ทีละข้อ ข้อไหนยังไม่ได้ทดสอบให้บอกตรง ๆ ว่ายังไม่ได้ทดสอบ
4. ภาพหน้าจอที่ระดับซูม 100% และ 150% อย่างละ 4 หน้า
5. อัปเดต `Documents/CHANGELOG.md` และ `Documents/TEST_PLAN.md`
