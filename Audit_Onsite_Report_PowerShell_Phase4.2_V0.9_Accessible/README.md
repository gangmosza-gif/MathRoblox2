### 2. ปุ่มขยายบนแถบหัว

- ปุ่ม `ก-` `ก` `ก+` พร้อมตัวเลขบอกระดับปัจจุบัน อยู่มุมขวาบน เห็นได้ทุกหน้า
- 4 ระดับ 100% 125% 150% 175%
- คีย์ลัด `Ctrl` และ `+` ขยาย, `Ctrl` และ `-` ย่อ, `Ctrl` และ `0` กลับค่าปกติ
- จำระดับไว้ใน `Config/UI_Settings.json` เปิดโปรแกรมครั้งหน้าได้ขนาดเดิม
- **ข้อมูลที่กรอกไว้ไม่หาย** เมื่อเปลี่ยนขนาด ทั้งข้อมูล 15 ช่อง ผลตรวจ 11 ข้อ แหล่งข้อมูลรายข้อ
  รายการไฟล์ Excel สถานะ Template บันทึกการทำงาน และหน้าที่กำลังเปิดอยู่

### 3. ขยายทั้ง Layout ไม่ใช่ขยายแค่ฟอนต์

ทุกขนาดพิกเซลในโปรแกรมผ่านฟังก์ชัน `Get-AuditScaled` เพียงจุดเดียว
ทั้งความสูงช่องกรอก ปุ่ม แถวตาราง ความกว้างเมนูซ้าย ระยะขอบ และคอลัมน์ตาราง
ถ้าขยายแต่ฟอนต์โดยไม่ขยายความสูง ตัวหนังสือจะถูกตัดครึ่งทันที นี่คือจุดที่พลาดกันบ่อยที่สุด

### 4. ปรับอื่น ๆ เพื่อการมองเห็น

- สีข้อความรองเข้มขึ้นจาก RGB 108,117,127 เป็น 90,99,110
- สีเส้นขอบเข้มขึ้นจาก 214,220,228 เป็น 196,205,215
- ปุ่มทุกปุ่มสูงอย่างน้อย 44 พิกเซล
- ขนาดหน้าต่างถูกจำกัดไม่ให้เกินพื้นที่จอจริง เวลาซูม 175% จะไม่เปิดมาแล้วล้นจอ
- ข้อความบอกข้อผิดพลาดบอกวิธีแก้ เช่น ผลตรวจยังไม่ครบ ให้ไปที่หน้า 3 เพื่อกรอกต่อ

## วิธีทำงานของปุ่มขยาย (สำหรับผู้พัฒนา)

1. `Start-AuditOnsiteUI` เป็นตัวห่อหุ้มที่วนลูป
2. `New-AuditOnsiteWindow` สร้างหน้าต่างจริงและคืนค่าว่าต้องเปิดใหม่หรือไม่
3. เมื่อกดปุ่มขยาย ระบบเก็บค่าที่ผู้ใช้กรอกทั้งหมดลง Hashtable บันทึกระดับซูมลงไฟล์ แล้วปิดหน้าต่าง
4. ตัวห่อหุ้มเรียก `Set-AuditUiScale` ด้วยค่าใหม่ แล้วสร้างหน้าต่างใหม่ พร้อมส่งค่าเดิมกลับเข้าไป

การสร้างหน้าต่างใหม่ทั้งบานพลาดยากกว่าการไล่เปลี่ยนฟอนต์ของคอนโทรลทีละตัวมาก
เพราะไม่ต้องกังวลว่าคอนโทรลไหนตกหล่น

## กฎเดิมที่ยังรักษาไว้ครบ

ข้อมูลรายงาน 15 ช่อง, ปุ่มจำค่า ล้างค่าจำ เริ่มสาขาใหม่, Export Gate ทุกชั้น,
ผลตรวจ Manual ใช้กับ Mapping ที่ยัง Pending ได้, Output เป็นไฟล์ใหม่เสมอ,
ไม่แก้ไขไฟล์ Excel ต้นฉบับ

## การรัน
`Run-AuditOnsiteReport.bat` เหมือนเดิม (Windows PowerShell 5.1, -STA, -NoProfile, -ExecutionPolicy Bypass)
