# UI Review: ปรับ UI ได้ขนาดไหนบน PowerShell 5.1

เอกสารนี้ตอบคำถามว่า ถ้าถูกล็อกไว้ที่ Windows PowerShell 5.1 แบบออฟไลน์ UI ของโปรแกรมนี้
จะทำให้สวยและใช้ง่ายได้ถึงระดับไหน และอะไรที่ทำไม่ได้

## 1. ข้อจำกัดที่เปลี่ยนไม่ได้

- PowerShell 5.1 มากับ .NET Framework 4.x จึงได้แค่ **Windows Forms** กับ **WPF**
- ไม่มี WinUI 3, ไม่มี Fluent, ไม่มี Acrylic, ไม่มี Mica, ไม่มีมุมโค้งของ Windows 11
- Windows Forms วาดคอนโทรลด้วย Win32 ล้วน ปุ่มและช่องกรอกมาตรฐานจะมีหน้าตาแบบ Windows Classic เสมอ
- ทำเงา ความโปร่งใส หรือ Animation ได้ยากมากและมักทำให้เกิดอาการกะพริบ
- ห้ามพึ่ง NuGet หรือ Library ภายนอก เพราะข้อกำหนดคือทำงานออฟไลน์ในเครื่อง

สรุปคือ **ทำให้ดูสะอาด เป็นระเบียบ และเข้าใจง่ายได้เต็มที่ แต่ทำให้เหมือนแอปสมัยใหม่ 100 เปอร์เซ็นต์ไม่ได้**

## 2. สิ่งที่ V0.8 ทำไปแล้ว (ระดับที่ทำได้จริงบน Windows Forms)

| เรื่อง | V0.7 | V0.8 |
|---|---|---|
| การวางคอนโทรล | พิกัดตายตัว หน้าต่างยืดแล้วเพี้ยน | TableLayoutPanel ทุกหน้า ยืดหดได้จริง |
| การนำทาง | ปุ่ม 4 ปุ่มบนหัว ทับกับ TabControl | เมนูขั้นตอนด้านซ้าย ไฮไลต์ขั้นที่ทำอยู่ |
| รู้ว่าต้องทำอะไรต่อ | ต้องกด Export ก่อนถึงรู้ว่าขาดอะไร | แถบสถานะและ Checklist บอกตลอดเวลา |
| ความคืบหน้า | ไม่มี | ตัวเลข 3 บรรทัด และ Progress Bar |
| ช่องที่จำเป็น | ดูไม่ออก | มีดอกจัน และพื้นสีอ่อนเมื่อยังว่าง |
| สถานะผลตรวจ | ข้อความในวงเล็บ | ป้ายสีแยก MANUAL / AUTO_DRAFT / AUTO_CONFIRMED |
| Export Gate | MessageBox ข้อความ 11 บรรทัด | หน้าต่างยืนยันแบบตาราง อ่านง่าย |
| การเลือกไฟล์ | ปุ่มเดียว ลบไม่ได้ | ลากวางได้ ลบทีละไฟล์ได้ เห็นขนาดและวันที่แก้ไข |
| คีย์ลัด | ไม่มี | F5, Ctrl+E, Ctrl+S, Ctrl+1-4 |
| ฟอนต์ | บังคับ Leelawadee UI | เลือกอัตโนมัติจากที่เครื่องมีจริง |

เทคนิคที่ใช้ทำให้ดูดีขึ้นโดยไม่ต้องพึ่ง Library
- ปุ่มแบบ FlatStyle = Flat กำหนดสีขอบและสี Hover เอง
- การ์ดพื้นขาววาดขอบ 1 พิกเซลและแถบสีด้านซ้ายด้วย Paint Event
- ป้ายสถานะใช้ Label ที่มี Padding และสีพื้นอ่อน
- DataGridView ปิด Visual Style เดิม แล้วกำหนดสีหัวตารางและแถวสลับสีเอง
- ใช้ชุดสีเดียวทั้งโปรแกรมจากไฟล์ Theme ไฟล์เดียว แก้สีทั้งแอปได้ที่จุดเดียว

## 3. ถ้าอยากไปไกลกว่านี้ ยังทำอะไรได้อีก (ยังอยู่บน 5.1)

ระดับ A ทำได้ ความเสี่ยงต่ำ
- ใส่ไอคอนเป็นไฟล์ .ico หรือวาดด้วย GDI+ แทนการใช้ตัวอักษร
- ทำหน้า Splash ตอนเปิดโปรแกรม
- ทำ Auto Save ร่างผลตรวจลง JSON เพื่อกันข้อมูลหายเมื่อปิดโปรแกรม
- ทำ Undo รายช่อง และปุ่มคัดลอกผลตรวจทั้งหมด
- Export Log เป็น HTML สรุปการทำงานของแต่ละสาขา
- แสดงตัวอย่างข้อความที่จะลง Word ก่อน Export (Preview รายข้อ)

ระดับ B ทำได้ แต่ต้องทดสอบเยอะ
- ย้ายงาน Scan Excel ไป Runspace แยก เพื่อไม่ให้หน้าจอค้างระหว่างอ่านไฟล์ใหญ่ พร้อม Progress Bar จริง
- ทำ Owner Draw ปุ่มและช่องกรอกให้มุมโค้งด้วย GraphicsPath
- ทำโหมด High Contrast และรองรับ DPI 150 เปอร์เซ็นต์อย่างเต็มรูปแบบ

ระดับ C เปลี่ยนเทคโนโลยี
- เขียน UI ใหม่เป็น **WPF + XAML** ผ่าน PresentationFramework ซึ่ง PowerShell 5.1 เรียกได้
  ได้มุมโค้ง เงา Animation Data Binding และ Style ที่ยืดหยุ่นกว่ามาก
  แต่ต้องรื้อโค้ด UI ทั้งหมด และ Debug ยากกว่า Windows Forms พอสมควร
  แนะนำให้ทำก็ต่อเมื่อ Phase 4.2 ปิดงานเป็น Final แล้วเท่านั้น

## 4. ข้อเสนอแนะลำดับงาน

1. ทดสอบ V0.8 ตาม Test Plan ให้ครบ โดยเฉพาะข้อ 1 ถึง 10 ที่เป็น Regression
2. ถ้าผ่าน ค่อยเลือกงานจากระดับ A ที่อยากได้เพิ่ม
3. อย่าเพิ่งทำระดับ C จนกว่างาน Mapping อีก 10 ข้อจะเสร็จ เพราะ Mapping คือความเสี่ยงหลักของโครงการ ไม่ใช่หน้าตา
